## 10. Cross-cutting structural finding: the self-serve module marketplace is non-functional for everything except FiscalNet

This emerged from checking reachability of claims in §1, §3, and §5, and is large enough to warrant its own section since it affects four separately-marketed features at once.

**Claim (repeated across multiple pages):** Kitchen Display, Table Service, Loyalty, and Saga XML export are real, available features — "included in Operations" (loyalty, kitchen display), "add-on for Starter," or "included in Pro plan" (Saga) — reachable by the customer via Settings.

**Verdict: FALSE as a self-serve claim, for all four, right now.**

Evidence chain:
- `IntegrationCards` (`components/app/IntegrationCards.tsx`) renders one card per entry in `MARKETPLACE_PRODUCT_ORDER` (`lib/billing/catalog.ts:189-191`), which is hardcoded to `["fiscalnet"]` only — despite `MARKETPLACE_PRODUCTS` defining five keys (`kitchen_display`, `table_service`, `loyalty`, `saga_export`, `fiscalnet`, `anaf_efactura`).
- The toggle action these cards would call, `setBusinessModuleInstalled` (`app/actions/org-settings.ts:143`), is fully implemented and correctly gates on entitlement — but has **zero callers** besides `IntegrationCards.tsx`, which never renders a form for anything but FiscalNet.
- `setTableServiceEnabled` (`app/actions/table-service.ts:1136`) is likewise fully implemented with **zero callers anywhere in the app** (confirmed via repo-wide grep).
- The Saga "deep link" the catalog advertises, `/app/settings/accountant?install=saga` (`lib/billing/catalog.ts:134,141`), leads to `app/app/settings/accountant/page.tsx:70`: `if (!orgRow?.saga_export_enabled) redirect("/app/settings?tab=integrations")` — this redirect fires **before** the page's own "Configurare Saga" install-steps card (`:90-106`) ever renders, sending the user back to the Marketplace tab, which (per above) never shows a Saga card to click. It is a closed loop with no exit.
- `lib/billing/stripe-sync.ts:165-167` only ever writes `saga_export_enabled: false` (on plan downgrade) — never `true`, anywhere in the codebase.
- Confirmed via repo-wide grep: there is no code path of any kind — self-serve UI, onboarding seed, or billing webhook — that ever sets `kitchen_display_enabled`, `table_service_enabled`, `loyalty_enabled`, or `saga_export_enabled` to `true` for any organisation.
- Separately, ANAF e-Factura OAuth (`app/api/anaf/auth/callback/route.ts`) is genuinely functional and stores real tokens, but `storeOrgTokens` (`lib/anaf/auth.ts:156`) never flips `efactura_enabled` to true, and `app/actions/efactura.ts:59` blocks invoice submission until that flag is true — so even a fully-connected ANAF account cannot send an invoice through the product today.

This is a different failure mode from the €199/commission pattern: the underlying feature code is real (kitchen display, table service, loyalty, and Saga export are all substantially implemented elsewhere in the app), and `marketplaceAllowsSelfInstall()` (`lib/billing/catalog.ts:193-199`) is explicitly designed to allow self-install for exactly these categories. The most likely explanation is that `MARKETPLACE_PRODUCT_ORDER` was trimmed down to `["fiscalnet"]` at some point (plausibly during the "lean product scope" work referenced elsewhere in the repo) without anyone updating the marketing copy, help articles, or FAQ that still describe these as available/included features.

## Pattern summary

Roughly **58 distinct factual claims** were checked across the six areas the task specified, plus two cross-cutting structural issues found while verifying reachability.

| Verdict | Approx. count | Notes |
|---|---|---|
| TRUE | 27 | Includes the offline queue, NIR, aggregated multi-site reporting, card-verification terms, HACCP module, EU/Ireland fiscal scoping, most resource-article content |
| FALSE | 13 | 2 live pricing errors (RO homepage FAQ €199/€99, Bit-Soft comparison €99), 1 onboarding catalog personalization claim, 1 offline self-contradiction, 1 VAT-rate translation error, ~7 dead-link instances (restaurants page + 5 distinct `/features/*` slugs), plus the loyalty/Saga "included" claims once reachability is counted |
| PARTIALLY TRUE | 6 | ANAF e-Factura "automat" overstatement, FiscalNet payment-code "mapped" overstatement, multi-site "compare locations" overstatement, Saga/loyalty claims (real code, unreachable UI) |
| GATED-BUT-REAL | 2 | Raport X FiscalNet command (works "when configured"), Saga export code path (real, just currently unreachable — borderline with FALSE, listed both places) |
| UNVERIFIED | 4 | TVA-hardcoding claim, "Raport Z în 2 minute" speed claim, the January-2025 B2B e-Factura fine claim, appointment-booking absence (confirmed absent, but "planned" can't be verified either way) |

**Does the €199/fake-commission pattern — a confident, specific, monetized claim with zero backend — repeat elsewhere? Mostly no.** The features/resources/lp copy in particular is unusually well-hedged ("we do not claim," "verify with your accountant," explicit non-availability notices for appointment booking and delivery-platform integration). The Glovo/Bolt Food/Tazz section is the clearest example of the product being **more honest than its own dead code** — real backend exists, but the marketing correctly says the integration doesn't exist rather than overselling it.

**What repeats instead is a different, arguably more operationally dangerous pattern: real features that became unreachable through configuration drift, with the marketing/help copy never updated to match.** Three variants of this showed up independently:

1. **Reachability rot** — `MARKETPLACE_PRODUCT_ORDER` was trimmed to `["fiscalnet"]`, silently making Kitchen Display, Table Service, Loyalty, and Saga export impossible for any customer to self-enable, while comparisons.ts, seo.ts, and the i18n FAQ still describe them as included/available (§10).
2. **Link rot** — `LEAN_PRODUCT_SCOPE_ENABLED` hid six `/features/*` explainer pages, but ~100 internal links across blog posts, industry pages, comparison pages, and the resources index were never updated, so real prospects hit live 404s today (§11).
3. **Partial-fix drift** — the already-known €199/€99 pricing error was fixed on `/pricing` but is still live, verbatim, in the homepage's own Romanian FAQ (`HomePageContent.tsx:35`) while the English version of the same FAQ was correctly fixed — meaning the fix didn't propagate to every copy of the same fact, and the uncorrected copy sits in the language the actual ICP (Romanian owners) reads.

None of these three is "we invented a number and a name for something that doesn't exist" (the €199/commission failure mode). All three are "the product changed and the words describing it didn't," across marketing, in-app copy, and help articles alike.
