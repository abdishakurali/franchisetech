## 1. Executive summary

- **The €199 "Assisted setup" price is real on the live pricing page right now** (`https://franchisetech.ro/pricing`, section "Configurare premium opțională": "Setup o locație - €199", "Lansare multi-locație - €349", "Setup fiscal la locație în România - €499") but has **zero fulfillment behind it**: no Stripe price ID (`lib/billing/plans.ts:141-169`, the `connectedPlan`/`setupOptions` objects have no `priceEnv`, unlike every real plan), no Cal.com integration anywhere in the code, no booking route. It is not just stale documentation — it is live customer-facing copy describing a product that cannot currently be purchased or booked through the app.
- **AGENTS.md's "Connected MCP Servers" list is entirely aspirational.** `~/.claude.json`'s project entry for this exact repo path has `"mcpServers": {}` and `"enabledMcpjsonServers": []`. No `.mcp.json` exists in the repo. None of supabase/stripe/resend/github/calcom/n8n-mcp/ZohoMCP are wired as MCP servers for this project, contradicting AGENTS.md's explicit list.
- **The partner/accountant "~20% recurring commission" program is a lead-capture form, not a commission engine.** The only backing table, `partner_waitlist` (migration `046_partner_waitlist.sql`), is documented in its own SQL comment as "Gated recruitment — no partner portal." There is no percentage-of-subscription calculation, no payout mechanism, and no Stripe Connect anywhere in the codebase. This is the same pattern as the €199 setup: detailed monetized copy, no backend.
- **CLAUDE.md's "Current deployment context" section is stale by design, not by accident** — its last real git commit is 2026-06-17 (`98bc50f`), the exact date it claims to be "as of." Nobody has updated it since. Concretely: migration level is claimed as "035" but the repo has 86 migration files, the newest dated 2026-08-31 (`20260831161809_single_truth_fk_indexes.sql`); the live release is `20260901_091151`, not `20260617_122603`.
- **Deploy is rsync of the live working tree, not a git checkout** (`deploy.sh:33-46`), and the working tree right now has 229 uncommitted changes, including to `CLAUDE.md` itself and to core files like `app/actions/kitchenops.ts` and `app/app/layout.tsx`. This structurally confirms production can (and, per already-established facts, did) receive code that was never committed to git — `RELEASE.json`'s `git_sha` field only records what `HEAD` pointed to at deploy time, not whether the tree was clean.
- **`docs/LEAN_REDESIGN_REPORT.md` describes a state that was later reversed.** It claims loyalty, table service, and the restaurant page were removed "from the primary public journey" — but `app/actions/loyalty.ts`, `app/app/settings/loyalty/`, `app/app/reports/loyalty-roi/`, `app/actions/table-service.ts`, `app/app/tables/`, and `app/industries/[slug]/` (which serves `/industries/restaurants`) all currently exist, and loyalty was added by real commits dated 2026-07-13 (`ca8fe19`, `69f0f4a`, `c5cca6b`) — after whatever "lean" pass this doc describes.
- **`docs/pos-competitor-research.md` is a leftover from a different product pivot**: it's titled "KitchenOps POS Competitor Research" (the brand `CLAUDE.md` explicitly blocks everywhere) and its entire competitor analysis targets "Irish café owners," not the Romanian ICP the rest of the repo describes.
- Biggest structural risk for the product owner: **the pattern of AI-authored docs stating specific, false "verified facts" with full confidence** — `docs/ONBOARDING_REDESIGN_PROMPT.md`'s claim that "the trial requires no card... do not reintroduce a card step" (flatly contradicted by a real, live, git-committed €1 card-verification feature) is the clearest example, but the €199/Cal.com/commission claims across marketing copy show the same failure mode: specific, confident, monetized claims with nothing behind them.

## 6. Partner-referral program findings

Two entirely separate mechanisms exist under the "referral" umbrella, and only one is real:

**A. Customer-to-customer referral (real, functioning as a discount mechanism):**
- `lib/referrals.ts` — `ensureReferralCode(orgId)` (line 22) reads/generates a `referral_code` on the `organisations` table via a SECURITY DEFINER RPC (`ensure_referral_code`), and lists rows from a `referrals` table.
- `creditReferral()` (line 62) and `creditReferralOnFirstPayment()` (line 78) call a `credit_referral` RPC that updates `referral_credit_months` on the referring org.
- Backing schema: migrations `015_referrals_trial.sql` and `016_referral_rpcs_and_unique_constraint.sql`. The `referrals` table's `credit_months` defaults to `1` (integer, `015_referrals_trial.sql`).
- This is a **free-months credit** system between two customer organisations — not a cash payout, not a percentage of revenue, no Stripe Connect. It is wired into real product surfaces: `app/app/layout.tsx:10,100`, `app/app/settings/page.tsx:22,149`, `app/app/reports/z-report/page.tsx:11,110`, `app/actions/onboarding.ts:7,161,436`.

**B. Partner/accountant commission program (marketing copy only — no backend):**
- Marketing copy (`lib/marketing/i18n/ro.ts:375-421`, `lib/marketing/i18n/en.ts:372-418`) describes accountants/consultants earning "~20% recurring" of a referred client's subscription for as long as they stay subscribed, plus "€100–150 on assisted setup activation on first activation" — with a worked example ("Pro at €79/mo → about €15.80/mo for you").
- The only backing code is `lib/partner-waitlist.ts` (`insertPartnerWaitlist`) and `app/api/partners/contact/route.ts`, writing to the `partner_waitlist` table (migration `046_partner_waitlist.sql`).
- That table's own SQL comment (`046_partner_waitlist.sql:1`) reads: **"Partner waitlist (gated recruitment — no partner portal)"**, and its RLS policies block all public select/insert/update/delete (service-role-only inserts via the contact API).
- There is no percentage-of-subscription calculation anywhere in `lib/` or `app/`, no commission ledger table, no payout scheduling, and zero `Stripe Connect` references (`grep -rn "Stripe Connect\|payout\|commission" lib app` matches only the marketing-copy files themselves).
- **Verdict: fake in the same sense as the €199 assisted setup.** The specific commission math ("~20%," "€15.80/mo," "€100–150") exists only as marketing prose; the actual system behind it is a lead-capture form the founder reviews manually in the Supabase dashboard.
